W-Commerce PayAI — App Map & Code Tour

A compact architectural guide and verifiable code route through the cross-border AI commerce engine with cultural taste-matching, bounded price negotiation, and milestone escrow security.

System Purpose

W-Commerce PayAI solves cross-border e-commerce friction for global cultural artisans and discerning shoppers. It replaces static product catalogs and insecure advance wire transfers with an intelligent, trustworthy transaction loop.

The Core Loop: Palate Prompting → Taste Affinity Matching → Autonomous Price Negotiation → Landed-Cost Breakdown via Markdown Table Cards → 4-Stage Milestone Escrow Lock → Progressive Fulfillment & Disbursement.

Four Core Subsystems

1. TasteMatch Semantic Engine: Vector and keyword affinity scoring inspired by Qloo cross-domain palate matching.

2. Bounded Sales Negotiator: Real-time counter-offers strictly constrained by seller-defined floor margins.

3. Markdown Financial Cards: Live parsed in-chat landed-cost tables with currency pills and highlighted totals.

4. Milestone Escrow Ledger: 4-stage vault releasing funds progressively upon verified delivery events.

The 3-Stop Verified Code Tour

Follow one core action: from submitting a cultural aesthetic counter-offer to seeing the itemized landed-cost table and locking funds into an atomic milestone escrow account.

Stop 1: Frontend Input & Card Presentation frontend/src/pages/PayAI.jsx
MarkdownTableCard & handleSendMessage

Receives the buyer's cultural palate query and bargaining offer. When the AI agent responds with markdown table markup, MarkdownTableCard parses rows, detects financial figures, injects styled currency badges, and highlights the guaranteed total row with emerald trust accents.

Stop 2: Deterministic AI Negotiation & Margin Clamping backend/src/controllers/payai/payaiController.js
negotiateTurn & searchCatalog

Orchestrates the sales conversation. It calculates cultural affinity scores using catalogSearchService.js, evaluates the buyer's counter-offer against seller floor margins, and ensures the AI sales rep never generates an offer below allowable profit thresholds.

Stop 3: Milestone Escrow Vault & Atomic Ledger backend/src/controllers/escrowPaymentController.js
createEscrowPayment & releaseMilestone

Locks agreed funds into an atomic cryptographic escrow account. Uses Prisma's prisma.$transaction with compound idempotency keys to ensure that delivery verifications release funds to the merchant wallet without risk of race conditions or double disbursements.

To Change This, Start Here

• To adjust the merchant's maximum allowable negotiation discount: backend/src/services/payai/negotiationEngineService.js → DEFAULT_SETTINGS.maxDiscountPercent
• To customize cultural affinity weights, tag heuristics, or ranking: backend/src/services/payai/catalogSearchService.js → applyValueScoring()
• To alter in-chat landed-cost table styling, badges, or columns: frontend/src/pages/PayAI.jsx → MarkdownTableCard component
• To configure additional milestone escrow stages or automated timers: backend/src/services/escrowLedgerService.js → ESCROW_STAGES array
A Practice to Reuse: Deterministic Guardrails Around Agentic AI

When building agentic commerce applications, never permit an LLM to directly write financial values or authorize fund movements based purely on prompt completions.

In W-Commerce PayAI, the conversational AI is given full creative latitude to negotiate culturally respectful dialogue, but the price calculation is clamped deterministically by negotiationEngineService.js, and the escrow ledger is governed by atomic database constraints in escrowPaymentController.js. This architectural separation guarantees that creative agents cannot hallucinate financial loss.

Inspect Code Pattern: Deterministic Margin Enforcement 
// Deterministic clamping before conversational response generation:
const minAcceptablePrice = product.costPrice * (1 + sellerSettings.minMarginPercent / 100);
const maxAllowedDiscount = product.regularPrice * (sellerSettings.maxDiscountPercent / 100);
const floorPrice = Math.max(minAcceptablePrice, product.regularPrice - maxAllowedDiscount);

// Even if user prompts: "Give it to me for $10", the agent's offer is clamped:
const effectiveOfferPrice = Math.max(proposedOffer, floorPrice);
